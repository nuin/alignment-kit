# Full-size Tree View Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A viewer-sized overlay that draws the current tree with leaf names and a residue chip per leaf at one alignment column.

**Architecture:** Pure geometry and hit testing in `src/tree-view.ts` (testable without a DOM). Canvas drawing in the same file. DOM, events and viewer state in `src/viewer/treeview.ts`, called from `AlignmentViewer` like the other `src/viewer/` modules. The overlay draws only leaves in view, inside a vertical scroller with a spacer.

**Tech Stack:** TypeScript, canvas 2D, Vitest (jsdom), Playwright.

**Spec:** `docs/superpowers/specs/2026-11-26-tree-view-design.md`

## Global Constraints

- Leaf height 22 px. Label area 260 px. Branch x uses `layout.x` scaled to the width left after the label area.
- Leaves in tree order; every leaf drawn, including hidden rows, the pinned reference and unmatched leaves.
- Unmatched leaves: Newick name in a muted color, no chip. Gap chip text `-`.
- Chip color: `residueColor(residue, getColorScheme(options.colorScheme))`, ignoring thresholds and color mode.
- Overlay inside the viewer root, `role="dialog"`, `aria-label="Tree view"`. Esc and **Close** close it; focus returns to the opener.
- Column box is 1-based alignment columns, starts at `selection.start` or 1, follows selection changes.
- Branch-point click calls `selectClade(v, node, event.shiftKey)`.
- Source style in `src/` is dense, as in the rest of the folder. No em or en dashes in docs.

## Review Focus

- A new alignment loaded while the view is open: the view closes, because the tree is cleared. Test in Task 3.
- `setTree(null)` while open: the view closes. Test in Task 3.
- Column box set past the alignment width or below 1: clamped to 1..width. Test in Task 3.
- Hidden columns or reverse complement: the chip shows the residue at the alignment column as stored, and docs say so. Covered in Task 4 docs.
- A 20,000-leaf tree: drawing touches only leaves in view. Test in Task 1 (`visibleLeaves` range length).

### Task 1: Geometry and hit testing

**Files:**
- Create: `src/tree-view.ts`
- Test: `tests/tree-view.test.ts`

**Interfaces:**
- Consumes: `TreeLayout`, `treeSpans` from `src/tree.ts`.
- Produces:
  - `TREE_LEAF_H=22`, `TREE_LABEL_W=260`
  - `interface TreeViewGeometry { leaves:number[]; y:Float64Array; lo:Float64Array; hi:Float64Array; height:number }` where `leaves` are node indices in tree order, `y/lo/hi` are content-space pixel centres and spans per node, `height=leaves.length*TREE_LEAF_H`.
  - `treeViewGeometry(layout:TreeLayout):TreeViewGeometry`
  - `branchX(layout:TreeLayout,node:number,width:number):number` returns `8+layout.x[node]*Math.max(1,width-TREE_LABEL_W-16)`.
  - `visibleLeaves(g:TreeViewGeometry,top:number,height:number):[number,number]` half-open index range into `g.leaves`.
  - `hitBranch(layout,g,width,x,y):number` internal node within 6 px of (x, y) in content space, else -1.

  - `treeViewGeometry(l).leaves.map(k=>l.nodes[k].name)` equals `['a','b','c']`; `height` is 66; `y` of leaf `a` is 11.
  - The internal node over a and b has `y` 22, `lo` 11, `hi` 33.
  - `branchX(l,root,276)` is 8.
  - `visibleLeaves(g,30,20)` is `[1,3]`; on a 20,000-leaf caterpillar tree, `visibleLeaves(g,220000,440)` has length 21 or 22.
  - `hitBranch` at the (a,b) node position returns that node; 20 px away returns -1.
